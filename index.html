HTTP Basics

HTTP (Hypertext Transfer Protocol) is an application-layer protocol used to transfer hypermedia documents (HTML, JSON, etc.). It follows a client-server model.

Request / Response Cycle

  1. Client sends a request (method + path + headers + optional body).
  2. Server processes and returns a response (status code + headers + body).
  3. Connection may be kept alive via headers to allow multiple requests on the same TCP connection.

Sample request

GET /index.html HTTP/1.1
Host: example.com
User-Agent: example-client/1.0

Client vs Server

RoleTypical software
ClientBrowsers, API clients
ServerWeb servers (Nginx, Apache), application servers

HTTP Methods

GET

Retrieves a representation of the resource. Should be safe and idempotent.

POST

Submits data to the server. Not necessarily idempotent.

PUT and DELETE

PUT updates a resource, DELETE removes it. Both are intended to be idempotent.

Short example: Status codes

  • 200 OK — successful GET
  • 201 Created — successful resource creation
  • 400 Bad Request — client error
  • 404 Not Found — resource missing
  • 500 Internal Server Error — server failure

Key Concepts

Statelessness

HTTP is stateless: each request is independent unless state is implemented via cookies/sessions.

Headers

Headers convey metadata (Content-Type, Authorization, Cache-Control) that affect how requests/responses are processed.

Status Codes

Numeric codes indicate request outcomes (1xx informational, 2xx success, 3xx redirection, 4xx client error, 5xx server error).

Security (TLS)

TLS (HTTPS) encrypts traffic between client and server to protect confidentiality and integrity.

Caching

Caching stores responses for performance; headers like Cache-Control and ETag control caching behavior.
