Common Methods

  • GET
  • POST
  • PUT
  • DELETE

GET

Retrieves a representation of the resource. Should be safe and unchanged.

Some important things to note about GET requests:

  • GET requests should never be used with sensitive data, as they can be cached and logged. They should not have side effects on the server.
  • GET requests can be cached by browsers and intermediate proxies, improving performance for repeated requests.
  • GET requests can be bookmarked and shared, as the parameters are included in the URL.
  • GET requests have length restrictions
  • GET requests can only request data not modify it

POST

Submits data to the server to create or update a resource.

Some important things to note about POST requests:

  • POST requests are not idempotent, meaning that making the same POST request multiple times can result in different outcomes (e.g., creating multiple resources).
  • POST requests can include a body with data to be processed by the server, such as form data or JSON payloads.
  • POST requests are not cached by default, as they typically involve changes to server state.
  • POST requests cannot be bookmarked or shared easily, as the parameters are included in the request body rather than the URL.
  • POST requests can be used to submit sensitive data, but should be sent over HTTPS to ensure security.

PUT and DELETE

PUT sends data to a server to create or update. POST AND PUT differ from each other as a Put request can be used mutiple times and produce the same unlike POST which can be used repeatedly but will produce different results each time a resource is created, DELETE removes the specified resource.

Short example: Status codes

  • 200 OK - successful GET
  • 201 Created - successful resource creation
  • 400 Bad Request - client error
  • 404 Not Found - resource missing
  • 500 Internal Server Error - server failure
